> Back-end é a camada que sustenta qualquer aplicação: APIs, bancos de dados, autenticação, filas, arquitetura e tudo o que roda no servidor sem o usuário ver diretamente. Este guia reúne roadmap, cursos gratuitos e pagos, documentação oficial de linguagens e frameworks, bancos de dados, ferramentas, arquitetura e boas práticas, comunidades e um capítulo dedicado a usar IA na prática no dia a dia de back-end — tudo verificado e organizado para quem está começando ou já atua na área e quer se manter atualizado.

## 🚀 Por onde começar

1. **Linux e terminal** — [Guia Foca](https://guiafoca.org/) explica desde o básico de um sistema GNU/Linux até administração e segurança, em português.
2. **Git e GitHub** — [Git4Noobs](https://github.com/DanielHe4rt/git4noobs) ensina o essencial sem assustar; pratique visualmente no [Learn Git Branching](https://learngitbranching.js.org/?locale=pt_BR) e no [Git School](https://git-school.github.io/visualizing-git/).
3. **HTTP** — [MDN — HTTP](https://developer.mozilla.org/pt-BR/docs/Web/HTTP) explica o protocolo que sustenta toda comunicação cliente-servidor.
4. **APIs** — leia [O que é uma API REST? (Red Hat)](https://www.redhat.com/pt-br/topics/api/what-is-a-rest-api) e depois pratique consumindo dados reais na lista [APIs Públicas](https://github.com/public-apis/public-apis).
5. **Escolha uma linguagem e um banco de dados** — veja as seções [💻 Linguagens e frameworks](#-linguagens-e-frameworks-para-back-end) e [🗄️ Bancos de dados](#️-bancos-de-dados) abaixo para comparar as opções mais usadas no mercado.

## 🤖 IA na prática

Back-end é uma das áreas onde IA generativa mais economiza tempo: código repetitivo (CRUD, migrations, testes) sobra, e os erros de um back-end mal revisado são caros (SQL injection, vazamento de dados, endpoint sem autenticação). Use a IA a favor da produtividade sem abrir mão da revisão.

**Para aprender**
- Peça para uma IA **explicar um erro de banco de dados ou stack trace** linha a linha e sugerir a causa mais provável, não só "a solução".
- Cole o `schema` de um banco e peça para gerar **consultas SQL comentadas** explicando cada cláusula (`JOIN`, `GROUP BY`, índices).
- Peça para **gerar uma API REST de exemplo** (rotas, controllers, validação) em uma linguagem que você está aprendendo, e depois pergunte "por que essa estrutura de pastas?".
- Peça **exercícios com gabarito** sobre o tópico que está estudando (autenticação, filas, cache, testes).

**Para trabalhar**
- Use [GitHub Copilot](https://docs.github.com/copilot), [Cursor](https://cursor.com/) ou [Sourcegraph Cody](https://sourcegraph.com/cody) para gerar testes unitários, migrations de banco de dados, documentação de endpoints (OpenAPI/Swagger) e refatorações mecânicas.
- Use assistentes de IA no console da nuvem, como o [Amazon Q Developer](https://aws.amazon.com/q/developer/), para gerar e explicar comandos de infraestrutura (IaC).
- Depois de **cada** sugestão aceita, rode a suíte de testes e o linter. Nunca aplique uma migration de banco gerada por IA direto em produção sem revisar.

**Limites e boas práticas**
- IA **inventa nomes de pacotes, métodos e parâmetros de API** que não existem (alucinação). Confirme sempre na documentação oficial antes de instalar uma dependência sugerida.
- Nunca cole segredos, tokens, strings de conexão de banco ou dados de clientes em ferramentas de IA sem a política de segurança da sua empresa.
- Revise manualmente qualquer código de autenticação, autorização ou manipulação de dados sensíveis gerado por IA — é a parte do back-end onde um erro sai mais caro.
- Entenda o que você aceita: em entrevista técnica e em produção, o código é seu, não da IA.
